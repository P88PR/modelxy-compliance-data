# KI-Compliance-Fakten (ModelXY)

Ein offener Datensatz zu Datenschutz- und Compliance-Angaben großer KI-Anbieter (AVV-Verfügbarkeit,
Trainingsnutzung von Eingaben, Verarbeitungsort, Unterauftragsverarbeiter, Speicherfristen u. a.) —
automatisch erzeugt und gepflegt von [ModelXY](https://modelxy.de), einer Such- und
Vergleichsplattform für KI-Modelle mit Fokus auf den DACH-Raum.

**Dieser Datensatz ist keine Rechtsberatung und keine Rechtsbewertung.** Jede Zeile ist eine
Tatsachenaussage — „laut Anbieterangabe", mit Beleg-URL und Prüfdatum — niemals ein Urteil wie
„DSGVO-konform" oder „rechtssicher". Was der Anbieter öffentlich sagt, kann sich ändern oder falsch
sein; prüft `evidence_url` selbst, bevor ihr euch darauf verlasst.

## Dateien

- `data/compliance-facts.json` — vollständiger Datensatz als JSON (ein Objekt mit `generated_at`,
  `license`, `source` und der Liste `facts`).
- `data/compliance-facts.csv` — dieselben Zeilen flach als CSV (für Tabellenkalkulation).

## Felder

| Feld | Bedeutung |
|---|---|
| `provider_slug` | Kurzname des Anbieters (z. B. `aws-bedrock`, `openai`) |
| `fact_slug` | Welches Compliance-Kriterium (z. B. `dpa_available`, `processing_location`) |
| `fact_name_de` / `fact_name_en` | Lesbarer Name des Kriteriums |
| `fact_explanation_de` / `fact_explanation_en` | Was das Kriterium bedeutet |
| `fact_value_kind` | `enum` (feste Werteliste `yes`/`no`/`partial`/`unknown`) oder `text` (Freitext, z. B. eine Region oder Tageszahl) |
| `value` | Der erfasste Wert |
| `qualifier` | Kurze Einschränkung/Präzisierung, falls vorhanden (z. B. „nur Enterprise-Tarif") |
| `checked_on` | Datum der letzten Prüfung (ISO 8601) |
| `is_stale` | `true`, wenn `checked_on` älter als 90 Tage ist — dann als prüfungsbedürftig zu behandeln |
| `evidence_url` | Die vom Redaktionsteam geprüfte Beleg-Seite |

Nicht enthalten: die ausführliche Recherche-Begründung je Fakt (interne Notiz). Wer mehr Kontext
braucht, findet ihn über `evidence_url`.

## Korrekturen vorschlagen

Ein Wert ist veraltet oder falsch? Bitte ein [Issue](../../issues) mit der betroffenen Zeile
(`provider_slug`/`fact_slug`) und einer aktuellen Beleg-URL eröffnen, oder einen Pull Request mit
Begründung stellen. Vorschläge werden redaktionell geprüft (dieselbe Sorgfalt wie jeder andere
Eintrag) und bei Übernahme in die Quelldaten eingepflegt — der nächste automatische Export
übernimmt sie dann hierher zurück.

## Aktualisierung

Dieser Datensatz wird automatisch erzeugt, sobald sich die zugrunde liegenden Quelldaten ändern —
keine manuelle Pflege in diesem Repository (bitte keine Änderungen direkt an den Daten-Dateien,
sie werden beim nächsten Export überschrieben).
